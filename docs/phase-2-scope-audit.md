# Phase 2 scope audit and proposed course correction

Review date: 2026-09-27. Baseline: `8b24717` (`feat(scenarios): add retained capture foundation`). Status: proposal awaiting approval; no implementation changes authorized by this report.

Course correction: freeze the existing evidence infrastructure. Stop expanding A/B readiness, generalized projection, and verified-retention machinery, and remove them from the proposed minimum scoring critical path. Do not immediately delete or rewrite them. Defer source deletion and breaking contract changes until real runs establish what is reusable. Pull forward a minimal Twin copy/run/inspect/discard slice, then let S12/S6, S13/S8, and guarded S9 experiments inform the final evidence/scoring design. AgentTX is strictly an external comparison target, never a Twin dependency.

## Part 1 — Evidence infrastructure

### Requirement boundary

[SPEC.md](../SPEC.md) requires five independent scoring fields and versioned JSON plus Markdown results. It requires checkable scenario conditions, not an attempt protocol or an evidence archive.

There is one historical distinction: **current** [ARCHITECTURE.md](../ARCHITECTURE.md) does describe normalized evidence, the attempt protocol, A/B readiness, and strict retained-artifact reopening. These were added during Phase 2. The initial architecture at `50fad88` describes clone, manifest/diff, receipt, apply, package boundaries, and versioned results; it does not require those frameworks. Later implementation documentation is not an independent product justification for continuing to expand them. Changing the documented contracts would require an explicit follow-up documentation/schema decision after approval, not silently changing v1 behavior.

The audit covers all eleven source files in `packages/scenarios/src/capture` and `packages/scenarios/src/contract`. Rows group related schemas, helpers, and validation rules by mechanism rather than listing type aliases separately. The full audit below preserves the original findings and keep/simplify/cut recommendations for historical review. Those labels are not an immediate refactoring or deletion plan: the freeze and reuse review supersede their timing. No source removal, rewrite, or breaking contract change is authorized here.

Preserve the mechanisms directly needed for the five SPEC fields: independent state observations, action start/block evidence, workspace inputs, output completeness, tool versions, cleanup status, direct evidence reasons/references, and pure evaluation. Their representation can be reconsidered only after real runs identify concrete needs. Existing contracts retain their current semantics while frozen; removing extra machinery from the proposed critical path does not mean silently weakening a v1 contract or fabricating fields to satisfy it.

Field abbreviations: **R** recovered/preserved; **P** reported; **B** blocked before execution; **W** workspace usable; **D** boundary accurately described. “None” means no direct evidence for a scoring field, even if the mechanism supports operations, privacy, or repeatability. For every such row, the reason identifies whether it is defensive/speculative or explicitly required elsewhere.

### Minimum evidence needed for trustworthy five-field scores

One run should carry the scenario/fixture version, tool/adapter version, original and actual execution workspace identity, required-input checks, ordered action and recovery observations, raw applicable outputs with completeness, documentation evidence, and cleanup errors. Each score carries an outcome, reason and a direct citation into that evidence. A small pure evaluator can initially be paired with manual output/documentation review.

Before/after bytes establish endpoint equality, not a history of preservation. A recovery claim needs observed damage followed by restoration through the evaluated tool's recovery operation. For a deterministic action restricted to the clone, original snapshots plus observed targeting can support scenario-scoped preservation; uncertain action scope leaves that distinction unknown. Blocked requires tool prevention before action execution; unsupported tool startup is not a policy block. Workspace usability is measured inside the tool's workspace. Tool reporting is evaluated from tool output, never the harness's diff. Documentation accuracy requires an actual version-matched claim.

This proposal does not relax the existing disposable-root, executable-trust, command allowlist, or cleanup protections around destructive tests. Those prevent benchmark accidents; they are distinct from the evidence archive. No existing mechanism has been removed or simplified in this audit.

### Smallest usable Twin core for Phase 3.0

1. **Clone a directory using plain recursive copy.** Include ignored and untracked files, dotfiles, and the local `.git` directory when present; work without Git. Preserve fixture bytes and executable modes. Allocate scratch outside the source tree and use independent file data, never hard links back to originals. Copy failure prevents launch. Initially reject unsupported symlinks/special files explicitly; never silently omit them or follow them into external data.
2. **Run the provided executable and argv with the clone as cwd.** Capture stdout/stderr, exit/signal/spawn errors and output completeness. Return a handle or provide a small lifecycle hook so the harness can inspect clone inputs before the action and clone effects before discard. Do not import scenario policy into core. The scenario adapter supplies the fixed guarded command; core remains agent-agnostic.
3. **Expose the run lifecycle sufficiently for comparison.** Distinguish clone failure, command start, completion and error. Keep the scratch copy available until required post-run observations finish. Support a timeout/cancellation path for the controlled scripts and settle the launched child before discard; full descendant-process accounting remains later product work and must be disclosed.
4. **Discard only the owned clone.** Track allocation/ownership and containment; refuse source/project/home deletion.
